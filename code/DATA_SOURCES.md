## Split rules

- Split by app, never by snippet. OVAA and InsecureBankv2 are held out completely and never appear in training files (`tests/test_core.py::test_no_test_app_text_in_training_data`).
- The synthetic generator was written without copying identifiers or strings from the test apps.
- Validation (loss monitoring only) is a separate synthetic draw (different seed).

## Labelling

- Test apps: every app file read in full (22 OVAA files, 13 InsecureBankv2 files after library filtering). Issues outside the 8 classes are recorded as `ignore` regions so a correct-but-out-of-scope report is neither rewarded nor punished.
- Training apps: labelled the same way; for allsafe and InjuredAndroid only fully reviewed files are used, so unreviewed issues cannot become wrong "clean" targets.
- Labels were produced with AI assistance (Claude) by reading the code, then printed line by line with `python data/check_labels.py` for human review. A human spot check is still recommended before relying on exact numbers.
- Synthetic labels are re-checked with per-class regex rules in `data/builder.py`; a failing sample stops the build.
